# design/sim

ASAP7 BSIM-CMG simulation netlists for the four drawn cells (decision 0010;
overview in `../README.md`). The adapted netlists `<cell>.osdi.sp` come in two
kinds with different provenance and different drift gates:

## The three hand-kept adaptations

`rx_cell.osdi.sp`, `tx_clk_cell.osdi.sp`, `rx_clk_cell.osdi.sp` were produced
once by klt's `adapt_extracted_netlist` and are kept by hand. Their line 2
states the true producer:

```
* Adapted from design/netlist/<cell>.sp by klt adapt_extracted_netlist (spec/decisions/0010); drift-checked by gen_cells.py --check.
```

Drift gate: `python3 -I design/gen_cells.py --check` re-renders each of the
three byte-for-byte from `design/netlist/` and exits 3 on drift. It runs in
`./check.sh` and in CI's item-1 freshness re-check
(`.github/workflows/signoff.yml`).

## `tx_cell.osdi.sp` — adapter-bound, with a knowingly false header

`tx_cell.osdi.sp` is bound to its producer: `design/sim/regen.py` re-runs
klt's `adapt_extracted_netlist` on `design/netlist/tx_cell.sp`, and the
committed bytes must reproduce that output exactly. They are sha256-pinned by
the committed tx_cell batch reports (append-only evidence): the current bytes
by `../sim/tx_cell.rows.r2.*.batch.report.json` (issue #297's netlist
closure), the pre-#297 bytes by the earlier `../sim/tx_cell.batch.report.json`
and `../sim/tx_cell.rows.*.batch.report.json`. Bound as
derived by the T1 item-1 attestation (`attest/item1.r9.json` ->
`evidence/item1.r14.json`). Hand-editing the file breaks that evidence.

Because of the binding, one defect stands on purpose: **line 2 still reads
`* Generated by design/gen_cells.py; do not edit by hand.` — false for this
file.** The adapter copies the source netlist's comment header verbatim and
offers no way to set the derived file's own provenance (tool gap:
2AMLogic/klayout-tools#6020), so a truthful line would mean editing pinned
bytes. It is left as-is and disclosed here rather than silently trusted.

Drift gates that do cover `tx_cell.osdi.sp`:

- CI re-hashes every item-1 inventoried file (`klt signoff --attest 1
  --inventory attest/item1.r9.json --check evidence/item1.r14.json` in
  `.github/workflows/signoff.yml`): any byte drift turns the `signoff` job
  red.
- `python3 design/sim/regen.py --check` (needs `klayout_tools`; no `-I`) is
  the semantic gate: it re-runs the adapter and exits 3 if the committed
  bytes no longer reproduce from `design/netlist/tx_cell.sp`. It is a
  local/reproduce command, not part of `./check.sh` (stdlib-only by design) —
  see `../README.md`, section Regenerate / check.

If `tx_cell`'s topology ever changes, the recorded evidence must be re-taken
(a new single-corner `klt sim` run and a new attestation record); do not
hand-edit this file to match.
